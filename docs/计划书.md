# AutoPlasm Nextflow 流程实现计划书

版本：v1.0 ｜ 日期：2026-10-15 ｜ 状态：进行中

## 1. 项目背景与目标

ABI 项目中的 `metagenomic_plasmid`（AutoPlasm）宏基因组质粒分析流程目前以 ABI 控制平面 + Python 运行时驱动。本项目将其以 **Nextflow DSL2** 独立实现，目标是：

- 产出不依赖 ABI Python 运行时、可直接 `nextflow run` 执行的独立流程；
- 覆盖全部五个测序平台（Illumina / ONT / PacBio HiFi / Hybrid / Assembly-only）；
- 覆盖 DAG 中定义的全部可选分析模块（binning、MAG、宿主关联、网络等）；
- 默认行为与 ABI 插件的 `config_default.yaml` 保持一致。

权威设计来源：`abi/src/abi/plugins/metagenomic_plasmid/pipeline_dag.yaml`（流程 DAG 与契约）、`config_default.yaml`（默认参数）。

交付目录：`trash_vibe_project/autoplasm-nextflow/`（与 abi 仓库平级）。

## 2. 范围

### 2.1 平台分支

| 平台 | 组装器（默认/备选） | 读长 QC | 宿主去除 | 丰度比对 |
|---|---|---|---|---|
| illumina | MEGAHIT / metaSPAdes | fastp (+FastQC/MultiQC) | bowtie2 | bowtie2 |
| ont | metaFlye（可选 medaka 抛光） | NanoPlot + Filtlong | minimap2 | minimap2 |
| pacbio_hifi | hifiasm-meta | HiFiAdapterFilt | minimap2 | minimap2 |
| hybrid | OPERA-MS / hybridSPAdes | 短读+长读全套 | bowtie2 + minimap2 | 长短读各一套 |
| assembly | 透传用户 FASTA | — | — | — |

ONT 额外支持 Dorado basecalling（POD5）与 BAM→FASTQ 转换。

### 2.2 分析阶段（对齐 DAG 的 category_dirs）

00 输入/basecalling → 01 QC → 02 组装 → 03 组装 QC(QUAST)+覆盖度 → 04 质粒检测与共识 → 05 质粒 binning → 06 分型 → 07 宿主预测与关联 → 08 注释 → 09 比较基因组 → 10 丰度 → 11 多样性/差异丰度 → 12 共现网络 → report。

### 2.3 工具清单

- **质粒检测**：geNomad（必选）+ 可选 PLASMe、PlasX、Platon、SCAPP；多工具共识（intersection / majority_vote / weighted_vote / single_tool，默认 weighted_vote：geNomad 0.6 / Platon 0.15 / PLASMe 0.15 / PlasX 0.1）；环化/末端重叠检测。
- **Binning（可选）**：PlasMAAG、gplas2、MOB-recon、SCAPP、Recycler。
- **分型**：PlasmidFinder + MOB-typer（默认）；COPLA、CONJscan、MacSyFinder（可选）。
- **注释**：Bakta + AMRFinderPlus + ISEScan + IntegronFinder（默认）；Prodigal、ABRicate、RGI/CARD、eggNOG-mapper、MOB-suite（可选）。
- **宿主**：MetaPhlAn4（默认）/ Kraken2 / PlasmidHostFinder；MAG 链（可选，默认关）：MetaBAT2/CONCOCT/SemiBin → CheckM2 → GTDB-Tk（可选 DAS Tool）。
- **宿主-质粒关联（默认关）**：共丰度相关（Spearman/Pearson）、序列相似性（k-mer/GC/密码子）、CRISPR spacer（minced）、长读桥接。
- **比较基因组**：MMseqs2 非冗余质粒目录（默认）；BLASTn、MUMmer、clinker（可选）。
- **跨样本统计（可选）**：alpha/beta 多样性（≥3 样本）、差异丰度（内部效应量法 / DESeq2，≥3 重复）、FastSpar 共现网络（≥20 样本）。
- **报告**：Markdown + HTML 汇总报告。

## 3. 技术方案

### 3.1 目录结构（nf-core 风格）

```
autoplasm-nextflow/
├── main.nf                  # 入口，按 params.platform 分发
├── nextflow.config          # 全部参数、资源 label、profile
├── subworkflows/            # illumina / ont / pacbio_hifi / hybrid / assembly / cross_sample
├── modules/                 # 每个工具一个 DSL2 module，按类别分子目录
├── bin/                     # 共识整合、结构检测、关联分析、差异丰度、报告等 Python/R 脚本
├── envs/                    # 每工具 conda 环境 yml
├── conf/test.config         # 测试 profile
├── assets/                  # 样本表模板与说明
└── README.md
```

### 3.2 关键设计

1. **参数体系**：镜像 `config_default.yaml`，如 `params.plasmid_detection_tools = ['genomad']`、`params.plasmid_binning_tools = []`、`params.consensus_method = 'weighted_vote'`；可选工具全部用列表开关，未启用不实例化、不阻塞下游（空通道处理）。
2. **内部 handler 脚本化**：ABI 中的 Python 内部步骤（共识整合、质粒结构检测、目录构建、共丰度/序列相似性关联、网络矩阵准备、效应量差异分析、报告生成）改写为 `bin/` 下的自包含脚本（标准库 + pandas 级依赖；DESeq2 为 R 脚本），由 process 调用，保证流程脱离 ABI 可独立运行。
3. **资源管理**：process 使用 label 分级（process_low / medium / high / high_memory），在 config 中集中映射 cpus/memory/time；MEGAHIT 默认内存上限 90 GB（对齐 ABI 的 96636764160 B 限制）。
4. **输出布局**：publishDir 严格对齐 DAG 的 category_dirs（`01_qc/`、`02_assembly/`、`04_plasmid_detection/` … `report/`），保留 ABI 产物的目录语义。
5. **环境管理**：`envs/` 提供每工具 conda yml（宽松版本 pin）；`-profile conda` 开箱可用，后续可补 docker/singularity profile。
6. **样本表**：单列 TSV，按平台需要提供 `sample_id, read1, read2, long_reads, assembly, pod5, bam, host_reference, group` 等列。

## 4. 数据库与资源

流程不自动下载数据库（与 ABI 策略一致）。需要用户预先准备并通过参数指定：geNomad DB、Bakta DB、MOB-suite DB、PlasmidFinder DB、MetaPhlAn4 DB、AMRFinderPlus DB、CARD、Kraken2 DB、GTDB-Tk、CheckM2、PLASMe/PlasX、COPLA、BLAST、PlasmidHostFinder。README 提供准备指引；未配置的数据库对应的可选步骤默认关闭。

## 5. 里程碑

| 阶段 | 内容 | 产出 |
|---|---|---|
| M1 | 骨架与参数体系 | main.nf、nextflow.config、目录结构、样本表模板 |
| M2 | 平台子工作流主干 | 五平台 basecalling/QC/组装/QUAST/覆盖度模块 |
| M3 | 质粒检测核心 | geNomad + 可选检测器 + 共识/结构脚本 |
| M4 | 下游模块 | binning、分型、注释、宿主、关联、比较基因组、丰度 |
| M5 | 跨样本与报告 | 多样性、差异丰度、FastSpar 网络、报告生成 |
| M6 | 验证与文档 | 语法/preview 验证、README、测试 profile |

## 6. 验证策略

- 本机若无 Nextflow/数据/数据库，则以语法级验证为主：`nextflow config` 解析、`-preview` 干跑（不执行工具）；在 README 明确标注验证边界。
- 不做生物学结果验证；真实数据的科学验证属于后续单独任务。

## 7. 风险与已知简化

1. ABI 内部 handler 的部分统计算法在独立脚本中为合理简化实现，与原实现的数值一致性未做回归对比（将列为后续工作）。
2. 可选工具众多，默认配置下仅核心路径启用；长尾可选模块经语法验证但缺乏真实数据冒烟。
3. 容器 profile（docker/singularity）首版仅预留接口，conda 为首要支持路径。
